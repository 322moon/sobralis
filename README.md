# Sobralis

Сервис поиска компании для прогулок, домашних встреч, вечеринок и поездок.

**Kotlin + Spring Boot + Spring Data JPA/Hibernate + PostgreSQL.** Модульный монолит с двумя бизнес-модулями: `users` и `events`.

Работают регистрация, HTTP Basic, события, заявки, одобрение/отклонение, выход и отмена. Частный адрес открывается после одобрения. Одновременные одобрения не могут превысить лимит мест.

## Запуск

Требуются Docker с Compose и интернет для первой сборки:

```bash
cp .env.example .env
docker compose up --build -d
docker compose logs -f app
```

API: `http://localhost:8080/api/v1`. PostgreSQL доступна локально на `15432`; порты настраиваются в `.env`. Пример пароля предназначен для локальной разработки.

Flyway создаёт схему, Hibernate проверяет её через `ddl-auto: validate`. Именованный volume сохраняет данные после перезапуска. Старая БД от `ddl-auto: update` автоматически не мигрируется.

Для запуска из IDE нужен JDK 21. Поднимите БД через `docker compose up -d db`, задайте в Run Configuration `DB_URL=jdbc:postgresql://localhost:15432/sobralis`, `DB_USER` и `DB_PASSWORD` из `.env`, запустите `main.kt`. Spring не читает `.env` автоматически.

## Проверка

При запущенном Docker и JDK 21:

```bash
./gradlew test
./gradlew bootJar
```

Testcontainers использует отдельную PostgreSQL. Проверяются права, валидация, приватность, миграции, откат транзакции и гонки одобрения/отмены. Отчёт: `build/reports/tests/test/index.html`.

## API

Пути ниже указаны после `/api/v1`. JSON - `camelCase`, время - ISO 8601 с часовым поясом.

Публичны регистрация, лента и карточка. Остальные запросы требуют Basic Auth с email и паролем. Проверка входа - `GET /users/me`; отдельного `/login` и токенов нет.

| Метод | Путь | Действие |
| --- | --- | --- |
| POST | `/users` | Регистрация, 201 |
| GET | `/users/me` | Мой профиль |
| POST | `/events` | Создание, 201 |
| GET | `/events?city=Москва&page=0&size=20` | Лента будущих активных событий |
| GET | `/events/{id}` | Карточка |
| POST | `/events/{id}/cancel` | Отмена, 204 |
| POST | `/events/{id}/applications` | Подать заявку, 201 |
| GET | `/events/{id}/applications` | Заявки для организатора |
| GET | `/events/{id}/applications/me` | Моя заявка |
| PATCH | `/events/{id}/applications/{applicationId}` | Решение: APPROVED или REJECTED |
| POST | `/events/{id}/applications/me/withdraw` | Отозвать / выйти |

Регистрация:

```json
{"email":"alex@example.com","name":"Алексей","password":"my-password-123"}
```

Создание события:

```json
{
  "title":"Настольные игры",
  "description":"Играем и знакомимся",
  "city":"Москва",
  "publicLocation":"Район Арбат",
  "privateAddress":"Адрес для подтверждённых участников",
  "startsAt":"2030-06-01T12:00:00Z",
  "capacity":5
}
```

`privateAddress` необязателен. В публичных полях указывайте только общедоступные сведения. Организатор определяется по аутентификации.

Одобрение или отклонение через PATCH:

```json
{"status":"APPROVED"}
```

Стандартные ошибки JSON, UUID и HTTP обрабатывает Spring через `ProblemDetail`. Бизнес-ошибки используют тот же формат с дополнительным `code`:

```json
{"type":"about:blank","title":"Conflict","status":409,"detail":"Свободных мест нет","code":"CONFLICT"}
```

400 - данные; 401 - аутентификация; 403 - права; 404 - объект; 409 - конфликт состояния/данных. Подробности неожиданных 500 остаются в логах.

## Правила MVP

- Событие сразу активно, редактирования нет. Организатор может отменить его до начала.
- `capacity` - 1..100 приглашённых **без организатора**. PENDING не занимает место.
- На событие одна заявка пользователя; повторной подачи после выхода или отклонения нет.
- Организатор принимает/отклоняет только PENDING. Пользователь отзывает только свою PENDING/APPROVED заявку до начала.
- После отмены изменения заявок запрещены; история остаётся в БД.
- Частный адрес видят организатор и одобренные участники активного события. Лента его не содержит. После выхода/отмены доступ участника закрывается.
- `page`: 0..10000, `size`: 1..100; город ищется без учёта регистра.
- Пароль: от 8 символов до 72 байт UTF-8, хранится BCrypt-хеш. Email приводится к нижнему регистру.

## Как устроен код

```text
users/ и events/
├── domain/                          # JPA-модели
├── application/                     # Сервисы и правила
└── infrastructure/
    ├── web/                        # Небольшие контроллеры
    └── persistence/                # Интерфейсы JpaRepository
```

Путь запроса: **контроллер → сервис → JpaRepository → PostgreSQL**. Реализацию репозиториев создаёт Spring Data. Отдельных классов-обёрток и дублирующих `Entity` нет.

Валидация и права находятся в сервисах. Контроллеры получают идентификатор текущего пользователя и вызывают сервис. `EventView` нужен для выдачи безопасной карточки; профиль пользователя не возвращает хеш пароля. Плоские заявки без связей/секретов возвращаются напрямую.

`@Transactional` объединяет изменения. Перед изменением заявки блокируется событие через `PESSIMISTIC_WRITE`. Изменения статуса загруженных сущностей Hibernate сохраняет при завершении транзакции (dirty checking); повторный `save` для них не нужен. Новые записи сохраняются через `save`.

Это простая слоистая архитектура: модули и бизнес-правила отделены от REST, но модели и сервисы связаны с JPA. Замена REST не требует изменения сценариев; замена технологии хранения затронет JPA-модели, репозитории и часть сервисов. Полной независимости от хранилища эта версия не обеспечивает - это компромисс в пользу простоты MVP.

Для разбора: `events/domain/Event.kt` → `events/application/EventService.kt` → `events/infrastructure/web/EventController.kt` → `events/infrastructure/persistence/EventRepository.kt`.

Flyway отвечает за миграции, Spring Security - за Basic Auth и BCrypt, JUnit/Testcontainers - за тесты. Spring обрабатывает стандартные ошибки через `ResponseEntityExceptionHandler`; свой обработчик добавляет бизнес-ошибки и безопасный 500.

MVP рассчитан на curl/Postman: CSRF отключён, cookie-сессий и CORS нет. Для браузерного клиента нужно пересмотреть CSRF-защиту, а для внешнего размещения использовать HTTPS.

Карты, чат, фото, платежи и продвижение остаются на следующие версии.
